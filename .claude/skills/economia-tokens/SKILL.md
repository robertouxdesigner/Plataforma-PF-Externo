# Economia de tokens

Objetivo: entregar exatamente o que foi pedido, gastando o mínimo de tokens.

## Escopo
- Faça **somente** o que foi solicitado. Nada de "já aproveitei e...".
- **Não crie** sem pedido explícito: arquivos extras, README, documentação, testes, exemplos, configurações, refatorações ou features "úteis".
- Não altere código que não faz parte da tarefa (formatação, renomeações, comentários).
- Se algo extra parecer realmente necessário, **sugira em uma linha** e espere confirmação — não implemente.
- Se o pedido for ambíguo e a escolha mudar o resultado, pergunte antes; caso contrário, use o padrão mais simples.

## Leitura e ferramentas
- Leia apenas os arquivos necessários; prefira ler trechos específicos a arquivos inteiros.
- Use busca (grep/glob) antes de abrir arquivos às cegas.
- Não releia arquivos que acabou de editar.
- Não use subagentes, a menos que o usuário peça.
- Agrupe chamadas independentes em paralelo.

## Código
- Solução mais simples que funciona. Sem abstrações para "uso futuro".
- Edite trechos (Edit) em vez de reescrever arquivos inteiros.
- Comentários só onde o código não se explica sozinho.

## Respostas
- Curtas e diretas. Sem introduções, sem repetir o pedido, sem resumo do que já está visível.
- Não cole código/arquivos inteiros na resposta se já foram salvos — cite o caminho.
- Ao final: 1–3 linhas dizendo o que foi feito e, se houver, o que ficou pendente.
- Não liste opções que não serão seguidas.
